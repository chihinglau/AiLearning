## 一、项目整体目标与范围

### 1.1 产品定位

**深爱学（AiLearning）** 是一款**专注于深圳地区中小学学生**的跨平台学习辅助应用。产品以深圳本地教材（人教版 / 粤教版 / 牛津深圳版等）为核心教研依据，提供分学段、分学科的**同步练习、错题本、知识点讲解、模拟测评、学情分析**等功能，帮助学生高效学习、助力家长科学辅导。

> **品牌命名决策**：中文名定为"深爱学"，英文名 **AiLearning**（对齐既有域名 AiLearning.com / AiLearning.cn）。"深爱学"是一个**三重呼应**的品牌名：① **地域呼应**——"深爱"谐音"深圳"，直接绑定深圳本地化属性；② **情感呼应**——"深爱学"= 热爱学习，正向情感表达，家长与学生都能共情；③ **中英文语义呼应**——Ai（爱）+ Learning（学）→ 深爱学，中文名与英文名语义天然对齐。不同于"智学通"/"智学网"这类 generic 竞品命名，"深爱学"兼具地域符号、情感温度与品牌记忆点。

### 1.2 核心价值主张

| 服务对象 | 核心价值 |
|---|---|
| **学生（6-18岁）** | 精准学情诊断 → 个性化练习推荐 → 错题闭环 → 成绩可视化进步曲线 |
| **家长** | 实时学情报告 → 知识点薄弱项预警 → 合理学习规划建议 → 学习时长管控 |
| **教师（可选C端延伸）** | 班级作业分发 → 学情批量分析 → 易错点集中突破 |

### 1.3 目标用户画像

| 学段 | 年级 | 核心学科 | 典型场景 |
|---|---|---|---|
| **小学** | 1-6 年级 | 语文 / 数学 / 英语 | 作业辅助、字词听写、口算练习、单元测 |
| **初中** | 7-9 年级 | 语文 / 数学 / 英语 / 物理 / 化学 | 中考复习、知识点串联、错题归纳 |
| **高中** | 10-12 年级 | 语文 / 数学 / 英语 + 选考科目 | 高考备考、模拟卷、考点精练 |

### 1.4 范围边界

#### ✅ 在范围内
- 三学段（小学/初中/高中）全学科学习辅助功能
- 安卓 + 鸿蒙双端原生体验（通过 Flutter 跨平台框架）
- 深圳本地化教材内容（人教版、粤教版、深圳牛津英语等）
- 家长端学情查看与学习时长管控
- 本地 AI 模型辅助的智能推荐（可选云端增强）
- 账号体系、云同步、会员体系

#### ❌ 不在范围内
- **直播授课**（一期专注自学辅助，不做在线教育直播平台）
- **教师端管理后台**（一期先做 C 端学生/家长双角色，B 端教师功能作为二期扩展）
- **硬件外设配套**（如智能笔、学习机等）
- **学科竞赛专项辅导**（一期聚焦日常同步学习与考试备考）
- **跨地区内容**（一期聚焦深圳本地教材版本，后续按需扩展广深珠三角）

### 1.5 竞品差异化

| 对比维度 | 深爱学 | 市场典型竞品 |
|---|---|---|
| **教材适配** | 深圳本地化（粤教版/牛津深圳版）深度适配 | 全国通用版为主，本地化弱 |
| **双端体验** | Android + HarmonyOS NEXT 原生级支持 | 多数仅 Android / iOS，鸿蒙支持弱 |
| **学情分析** | 知识点图谱 + 薄弱项定位 + 进步趋势 | 多数仅错题统计，缺少结构化分析 |
| **AI 能力** | 本地模型优先，隐私安全，低延迟 | 依赖云端大模型，有网络和隐私成本 |
| **家长角色** | 学习时长管控 + 知识点预警 + 数据透明 | 多数只有"看进度"，无法管控 |

### 总体原则

> **三个阶段，每阶段独立可交付、可运营、可盈利**。每个阶段的交付标准是"该学段上线即可独立支撑运营"，而非"全部功能一次性堆完"。

## 三、跨平台双端适配架构设计

### 3.1 整体架构选型：Flutter + Platform Channel（沿用现有项目范式）

参考现有 `RetroEmuPouch` 项目（[design-account-cloud-ads-membership.md](file:///d:/ai/prj/trae/HuaWei/AiLearning/docs/design-account-cloud-ads-membership.md)）中已验证的 Flutter 跨平台 + PlatformPal 抽象层架构，本应用沿用同一范式：

```
│  ┌────▼──────────────▼──────────────▼──────────────▼──────────────▼────┐ │
```

### 3.2 Flutter OHOS 支持方式

**关键背景**：HarmonyOS NEXT（纯鸿蒙系统）**不兼容 Android APK**，需要使用华为官方的 **Flutter OHOS 版本**（由华为/OpenHarmony 社区维护）。

| 方案 | 说明 | 选型 |
|---|---|---|
| **A（推荐）** | Flutter OHOS 社区版（华为维护）+ 统一 Dart 业务代码 | ✅ 沿用现有 RetroEmuPouch 已验证的方案 |
| B | 纯鸿蒙 ArkTS 重写 | ❌ 双份代码维护成本高 |
| C | WebView 套壳 | ❌ 性能差、体验差、应用商店审核难 |

**现有项目已验证**：RetroEmuPouch 项目已成功构建 HAP 包并在鸿蒙设备（Pura 70）上真机运行，`PlatformPal` / `AndroidPal` / `OhosPal` 抽象层模式成熟。

### 3.3 PlatformPal 接口层设计

本应用在现有 RetroEmuPouch 抽象层基础上，扩展教育类应用特有的平台能力：

```dart
// —— 账号与认证 ——
abstract class AccountPal {
  Future<AuthResult> loginWithPhone(String phone, String code);  // 手机号+验证码
  Future<AuthResult> loginWithWeChat();                           // 微信一键登录
  Future<AuthResult> loginWithHuawei();                           // 华为账号登录（鸿蒙端）
  Future<void> bindChildAccount(String parentToken, String childProfile); // 家长绑定儿童
}

// —— AI 能力（本地推理优先）——
abstract class AiPal {
  Future<AiResponse> ask({required String prompt, AiContext? context});
  // 意图识别、语义理解、本地 NPU 推理
}

// —— 语音能力（听写 / 跟读评测）——
abstract class SpeechPal {
  Future<String> getSpeechToken();                    // 获取语音识别 token
  Stream<SpeechResult> recognizeStreaming();          // 流式语音识别（听写）
  Future<PronounceScore> evaluatePronunciation();      // 跟读评测（英语）
  Future<void> speak(String text, {String? lang});     // TTS 朗读
}

// —— 学习时长管控（家长端）——
abstract class ScreenTimePal {
  Future<ScreenTimeStatus> queryDailyUsedMinutes();   // 今日已用时长
  Future<void> setDailyLimit(int minutes);            // 设置每日限额
  Stream<void> getLimitReachedEvent();                // 达到限额事件流
}

// —— 应用商店 ——
abstract class BillingPal {
  Future<PurchaseResult> purchaseMembership(String sku);  // 会员购买
  Future<bool> restorePurchases();                         // 恢复购买
}
```

### 3.4 双端差异点清单

| 能力点 | Android 实现 | HarmonyOS NEXT 实现 | 说明 |
|---|---|---|---|
| 账号登录 | 手机号+短信验证码 / 微信 SDK | 华为账号 OAuth / 华为 IAP 一体化 | 鸿蒙端无 GMS，必须用华为 HMS |
| AI 推理 | 可选 华为 HiAI / NCNN / ONNX Runtime | 原生 NPU（HiAI 2.0 / 3.0） | 鸿蒙 NPU 能力更强，优先本地推理 |
| 语音识别 | 腾讯云 ASR / 百度 ASR | 华为 Petal Speech | 都有平台限制 |
| TTS 朗读 | Android 原生 TTS / 第三方 SDK | 鸿蒙原生 TTS / 华为 Petal TTS | |
| 广告 SDK | Google AdMob | 华为 Petals Ads | 双端完全不同，PlatformPal 隔离 |
| 应用内支付 | Google Play Billing | 华为 IAP | 服务端校验链路分平台 |
| 推送通知 | Firebase Cloud Messaging | 华为 Push Kit | |
| 文件存储 | Android 分区存储（Scoped Storage） | 鸿蒙沙盒文件系统 | 抽象层处理差异 |

## 四、前后端技术栈选型

### 4.1 选型原则

> **最大化复用现有项目技术资产**（RetroEmuPouch 已验证的后端 FastAPI + PostgreSQL 技术栈、Flutter 跨平台范式、PlatformPal 抽象层模式），在此基础上扩展教育类应用所需的内容管理、AI 服务、学情分析等能力。

### 4.2 前端（Flutter 客户端）

| 维度 | 选型 | 版本/说明 | 理由 |
|---|---|---|---|
| **框架** | Flutter | ^3.41.x（与 RetroEmuPouch 对齐） | 现有项目已验证 Flutter OHOS 构建链路 |

## 六、数据安全与合规方案

### 6.1 监管框架总览

教育类应用（特别是面向未成年人的）受到**多层监管**。本方案按以下合规优先级设计：

| 监管文件 | 核心要求 | 优先级 |
|---|---|---|
| 《个人信息保护法》PIPL | 最小必要、告知同意、数据安全评估 | **P0** |
| 《未成年人保护法》 | 未成年人个人信息保护、沉迷防控 | **P0** |
| 《儿童个人信息网络保护规定》 | 14 岁以下儿童信息需监护人同意、专人管理 | **P0** |
| 《教育移动互联网应用程序信息服务管理办法》 | **教育 APP 备案**、内容审核、数据安全 | **P0** |
| 《App 信息收集基本要求》+《第三方 SDK 收集规则》 | 明示收集、禁止强制收集非必要信息 | **P0** |
| 华为 AppGallery / Google Play 政策 | 隐私政策、Data Safety、目标 API | **P0** |

### 6.2 合规重点清单（深圳本地化）

| # | 合规项 | 具体要求 | 实施方式 |
|---|---|---|---|
| 1 | **教育 APP 备案** | 深圳地区运营的教育 APP 需向广东省教育厅 / 深圳市教育局备案 | Phase 1 M1 启动，随软著/APP 备案同步办理 |
| 2 | **软著（APP 版本）** | 国内商店上架必需 | Phase 1 M1 提交（加急 10-30 天） |
| 3 | **数据本地化存储** | 教育数据不得出境，核心用户数据存深圳/华南节点 | 阿里云 ECS 选深圳可用区 |
| 4 | **14 岁以下同意机制** | 儿童账号需监护人明示同意 | 家长端扫码绑定 = 监护人同意 |
| 5 | **学习时长管控** | 每日时长上限（家长可设默认≤180分钟） | Phase 1 家长端 P0 功能 |
| 6 | **消费限制** | 未成年人会员购买需家长二次验证 | 鸿蒙/Android 应用内支付前验证 |
| 7 | **第三方 SDK 披露** | 隐私政策逐条列明 | 复用现有 CMS 隐私政策管理 |
| 8 | **AI 内容审核** | AI 生成的学习辅导内容需可追溯、不违反教育规律 | Prompt 模板 + 模型输出过滤规则 |

### 6.3 数据分类分级保护

| 数据分类 | 举例 | 敏感级别 | 存储位置 | 保护措施 |
|---|---|---|---|---|
| **核心敏感** | 儿童姓名 / 学校 / 年级 / 家长手机号 | 极高 | PostgreSQL + AES-256 加密字段存储 | 服务端字段级加密 + 严格权限审计日志 |

| **公开内容** | 教材章节 / 题库 / 知识点讲解 | 公开 | CDN 对象存储 | 版本化管理 + 内容审核工作流 |

```
│ • 微信一键登录（需关注防滥用）                                 │
│ • 华为账号 OAuth（鸿蒙端）                                    │
│ • JWT access_token（15 min） + refresh_token（30 d）           │
│ • 异地登录检测 + 短信通知                                     │
│                                                               │
│ Layer 3 —— 数据层                                             │
│ • 密码 bcrypt 哈希存储（盐独立）                               │
│ • 核心敏感字段 AES-256 字段级加密                              │
│ • PostgreSQL pgcrypto 扩展辅助                                │
│                                                               │
│ Layer 4 —— 审计层                                             │
│ • 所有敏感操作写入审计日志                                     │
│ • 家长操作独立审计流                                           │
│ • 定期安全审计（自动 + 人工）                                  │
└─────────────────────────────────────────────────────────────┘
```

| R8 | **团队能力缺口**（AI 推理 + 教育内容双领域） | 中 | 交付质量 | Phase 1 先做规则引擎推荐（低 AI 依赖），AI 能力渐进引入 |
