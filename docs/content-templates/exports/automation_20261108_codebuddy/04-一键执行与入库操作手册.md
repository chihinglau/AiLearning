### 2.0.1 manifest 三列语义与「已入库」三态（第十一轮整改）

`_import-manifest.json` 的每条记录有三个哈希列，**含义不能混**：

| 列 | 含义 | 谁能改 |
|---|---|---|
| `imported_sha256` | **导入当刻**的字节 sha | **永不改写** |
| `current_file_sha256` | 盘上现值 | 每次入库更新 |
| `imported_content_sha256` | 导入当刻**剔除元数据键**（`_legacy` / `_legacy_note`）后的内容哈希 | 每次入库更新 |

校验器（`docs/content-templates/_validate_daily.py::_manifest_import_state`）据此判三态：

| 状态 | 条件 | 输出 | 影响 |
|---|---|---|---|
| `unchanged` | 字节与导入当刻一致 | `[已入库] 与 manifest 的 imported_sha256 一致……` | 重名/多选闭合按**提醒**（不阻断） |
| `meta_only` | 字节不同、**内容**哈希一致（只补了 `_legacy` 标记这类元数据） | `[已入库·仅元数据变更] 字节与导入当刻不同，但剔除元数据键后内容一致……` | 仍按已入库口径（不阻断） |
| `changed` | 字节与内容都不同 | `[文件已变更·未重导] 内容与导入当刻不同……` | 按新版本**从严**（重名报错） |

> 为什么要拆列：第十轮给 8 份 11-07 math JSON 打 `_legacy` 标记时，为了不让校验器假红，
> 把 manifest 里这 8 条的 `sha256` **就地刷成了当前文件版本**——于是 manifest 记的从
> 「导入当刻那一版」变成了「盘上现值」，**「已入库」的判据被降级成「这个文件被登记过」**：
> 任何对内容的就地改写，只要顺手刷 sha，校验器仍会说「已入库」。拆成三列 + 内容哈希后，
> 「刷 sha 就能骗过校验」这条路被堵死：内容变了就是 `changed`，从严检查。
> 迁移留痕：`_archive/_import-manifest.pre-3col.json`（逐字节副本）+
> `_archive/_import-manifest.pre-3col.provenance.txt`（49 条逐条明细：41 条 unchanged / 8 条 legacy_meta_only）。

```text

```

并附一份同名 `.provenance.txt`（改了什么、怎么改、sha256）。示例：`_archive/english_g1_first_20261107.pre-remap.json`（第七轮 remap 之前，sha256 与 manifest 里的导入期 sha 一致，可当原件用）、`_archive/english_g1_first_20261107.pre-q4-add.json`（补第 4 题之前）。

`audit` 支持 `--current <db>` 指定目标库（例如只对比两个备份之间的差异：`--since A.db --current B.db`），默认对比当前 `settings.database_url` 指向的库。

#### 3.1.1 `db_op_*.json` 统一骨架与历史字段映射（第十二轮整改）

**统一骨架（新脚本一律按这套输出）**：


#### 3.1.2 写盘前比字节（第十二轮整改）

`mtime` 是这套体系里「这个文件何时被动过」的唯一证据。**任何脚本写盘前先比字节，一致就不落盘**：

- `migrate_manifest_3col.py`：manifest 已是 schema v3 且三列一致 → 打印「[幂等] … 本次不落盘、不改 mtime」直接返回（实测复跑后 manifest mtime 仍是 `22:03:22`）。
- `mark_legacy_json.py`：本次零变更时不写 manifest、**也不重写留痕文件**（早前它会无条件重写 `math_11-07_legacy-mark.provenance.txt`，把「逐份明细」清空——已修，并按原文还原该文件）。
- 通用写法：`write_if_changed(path, text)`（比 `path.read_bytes()`，一致返回 False）。

> 实例：`daily\math\g9\math_g9_first_20261108.json` 的 mtime 停在 22:04，但 sha 与导入当刻完全相同——内容一字未改地被重写了一遍，只有 mtime 变了。这类「无谓 touch」会让以后的审计误判，不要再做。

- 执行前必须先留**逐字节副本**（`_archive/<name>.pre-*.json`）+ provenance 记录新旧 sha；
- 执行后必须同步 manifest 的**当前值**（`current_file_sha256` / `imported_content_sha256`），
  **但 `imported_sha256` 不改**（那是导入当刻，永不改写）；
- manifest 三列语义与「已入库」三态判定见 `04` §2.0 之后的补充说明与
  `docs/content-templates/_validate_daily.py::_manifest_import_state`。

## 6. 目标库与真机验证（最容易踩的坑）

**App 不需要重构、不需要重新打包**：Flutter 客户端没有内置题库，知识点/章节/题目全部走 HTTP 实时拉取（`app\lib\core\constants\app_constants.dart` 的 `API_BASE_URL`）。只有 API **地址**变更或后端换 PostgreSQL 才需要改构建参数。

但「导入成功」≠「真机能看到」，必须确认后端进程读的是哪个库：

```powershell

(Invoke-RestMethod 'http://127.0.0.1:18080/api/public/knowledge-points').Count

```

- 目标库取 `backend\app\core\config.py` 的 `settings.database_url`，默认 `sqlite:///./ailearning_dev.db`（相对 `backend` 工作目录）；`DATABASE_URL` 环境变量 / `backend\.env` 可覆盖，目前 `.env` 不存在。
- **`dev` 与 `device` 是两份独立库**：`docs\content-templates\README.md` 明确真机联调常用 `ailearning_device.db`，且各有专用 manifest（`_import-manifest.json` / `_import-manifest-device.json`）。
- 2026-11-08 实测：首轮导入后 `dev` = 596 知识点 / 1058 题（12 个新知识点全命中），10:22 补题后 `dev` = **596 / 1086**；`device` = 581 / 1004；而 18080 后端 API 返回 **581**、新知识点 **0/12** → 后端当时没读到新数据（库分叉或旧进程持有旧句柄）。**通用解法：重启后端并确认环境变量**，不要靠刷新页面；重启后再用上面的计数命令复核 API 是否等于目标库。

```powershell

Push-Location $Be

```

## 7. 参数速查

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Action` | `run` | **仅 `run_all.cmd`**：`run`=计划+全科提示词、`plan`=只看计划、`prompt`=只出提示词、`verify`=核实。**仅 `ops.cmd`**：`import`=备份+入库、`import-dry`=备份+试跑、`restore`=回退（由 `db_ops.py` 承担，必须另带 `-ConfirmToken I_KNOW`，教研会话禁止调用）。两个入口的 Action 集合不重叠 |
| `-Date` | 当天 `yyyyMMdd` | BATCH_DATE，全程固定，换日才变 |
| `-Shift` | `02` | `02` 进攻班 / `12`、`22` 补漏班（逻辑班次标识，不依赖定时器；`22` 在 CodeBuddy 载荷里已前移到 21:30–21:38，见 `03` 与 `00`） |
| `-Strict` | 关 | `verify` 时把缺文件与内容提醒也判为未通过 |
| `-Json` / `-OutFile` | 关 / 空 | 机器可读输出 / 另存提示词 |
| `-BackupPath` | 空 | `restore` 必填，指定要恢复的备份 `.db` |
| `-Overwrite` / `-ConfirmToken` | 关 / 无 | 仅 `ops.cmd`：`-Overwrite` 把已存在题目的字段（如 `difficulty`）同步入库，不传则同题干题按幂等跳过；`-ConfirmToken I_KNOW` 必须人工显式传入，未传即拒绝写库 |

单学科补救用 `run.cmd`（`-Subject` / `-Grade` / `-Grades` / `-Minutes` / `-DryRun`），例如内容已写好但没收尾：

```powershell
& "$Root\docs\content-templates\exports\automation_20261108_codebuddy\run.cmd" -Action commit -Subject math -Grade 1 -Date $Date -Minutes 5 -DryRun
```

## 8. 为什么可以反复调用

- **同日重跑**：`all-plan` 每次重算，当天文件已存在且自检通过 → `done/skip`；不重写、不加 `_r2`、不重复出题；只补 `missing`、修 `repair`。
- **入库重跑**：manifest 相同 hash + `status=ok` 自动跳过，全表增量 0；每次仍会先备份（多一份快照，无副作用）。
- **断点续做**：46 个年级分批跑完，已完成年级已逐年级落盘，下次原样重跑同一命令接着做。
- **换日不卡同一节**：`progress_of()` 按大纲顺序 + 历史 JSON 的 section/chapters 名算 `next_section`，今天只做这一节；每次 `commit` 把真实 section 与具体下一节写进台账/日志；同一节连续 ≥2 天会提醒标注或推进；全册覆盖完进入第二轮或零新增。补漏班不推进新节。
