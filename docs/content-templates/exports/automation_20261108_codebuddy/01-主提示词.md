【硬约束 · 与原文一致】
- 单元/节必须来自 baseline\_outline_{SUBJECT}_{semester}_latest.md（按 tasks.json 的 outline 字段）中本年级那一节；清单外不写；大纲缺该年级则停止并报告。章节名用教材原名，order_index 取大纲序号。
- **章节推进（防重复做同一节）**：`plan.grades[].next_section` 与 `context` 的「今日进度指针」由脚本按「大纲顺序 + 历史产出里的 section/chapters 名」算出，**今天只做 next_section 指明的那一节**（`next_unit` 写 chapters.name，`next_order` 写 order_index）；不回头重做已覆盖节、不跳节；一节内容多可拆 2 天但必须在台账标注「同一节第 N 天」。若进度指针显示全册已覆盖，按原文进入第二轮（加深/换情境/跨章综合）或走零新增处理，不得靠换几个字重复出题。补漏班例外：只修当天已有文件，不推进新节。
- **英语 section 命名（防串单元）**：英语按课时板块推进时，`knowledge` 的 `section` 必须写「Unit N 标题 / 板块」复合名（如 `Unit 1 What is your family like? / Ready Go`），point 的 `parent` 与它完全一致，`chapters[].name` 仍是完整单元名。`Ready Go` / `Story` 这类纯板块名在 6 个单元里重复，`_validate_daily.py` 按「(单元, 板块) 二元组 + chapters 单元一致性」校验，越界或串单元一律 `[错误]`，不再因「已入库」降级为提醒。整单元首跑的历史节点允许保留单元名，不要为凑格式编造板块；台账与运行日志的「下一节计划」写复合名，大纲只有单元名、没有课时板块的年级（如英语 g9）沿用单元名，不要拼成 `X / X` 这种重复名。
- `commit` 会把本次真实写下的 section 与脚本算出的「下一节计划：具体节名」追加进台账和运行日志（不再写占位文本），次日从这份记录继续；同批次重复 commit 幂等。
- 每年级 3~6 个知识点 / 18~28 道题（每点 ≥4 题）；本文件必须重声明 section 且只写 node_type/name/order_index；point 的 parent 与 prerequisites 只引用本文件名称；题目优先挂本文件 point；至少 4 种题型且含 1 多选、1 主观；difficulty 为 1~5 整数，1-2:3:4-5 ≈ 4:4:2；多选题解析逐项写 A/B/C/D 与 ✓/✗；带计算的题解析写算式；题干独立可答、不依赖图片、不与已有题干重复。
- **【硬约束 · 生成期按住分布】** 40/40/20（±15pp）与「每点 ≥4 题」必须在**出题时**就设计好：difficulty 由题目本身难度决定，不得先随意打标签再事后批量调档凑比例；分布不达标只能补题或换题。禁止用补丁脚本改写已通过自检的 JSON 来消掉 `all-verify` 的提醒；这一步的边界例外只有人工运维的 `ledger-sync`（且需 `--confirm I_KNOW`）。**「每点 ≥4」是 fail 级**：`verify_one` 判 errors，`all-verify` 不通过、入库第 2 步直接中止——只有 3 题的批次不再能过关。生效日 20261108（更早的历史批次只提醒不判失败，见 `04` §2.0）。

## 边界

- 原文（设计文档 + `exports\automation_20261108\` 五个文件）**一个字都不改**；本目录是新增的改写版。
- 驱动脚本默认只读；只有 `lock --action acquire`、`commit`、`finish` 有写动作，且 `commit/finish` 支持 `--dry-run`。
- 自检脚本必须用内容根下的 `_validate_daily.py`：它按 `__file__` 所在目录找 `baseline\` 与 `_import-manifest.json`；导出包里那份副本所在目录没有 `baseline\`，直接跑会丢大纲范围校验。
