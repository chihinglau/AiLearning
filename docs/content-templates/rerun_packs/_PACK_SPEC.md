# 重跑内容包编写规范（所有 pack 共用，2026-11-10）

本文件是 34 册重跑内容包的唯一规格说明。生成任何一册前必须完整读它，
并读黄金样例 `rerun_packs/politics_g2.py` 与骨架索引
`exports/review_20261110/rerun_skeleton_index_20261110.json`。

## 1. 目标

按「年级知识点表」重跑整册教研数据，产出**真实学科内容**，
替换评审判定不合格的模板套话册。产出先落 `daily_rerun/` 待评审区，
**不写 `daily_consolidated/`、不改隔离名单、不入库**。

## 2. 数据结构

```python
PACK = {
    "subject": "<学科代码>",
    "grade": <年级整数>,
    "version": "<教材版本>",
    "semester": "first",
    "chapters": [
        {
            "name": "<骨架索引里的官方章名，逐字一致>",
            "summary": "<本章真实内容摘要>",
            "points": [
                {
                    "name": "<节级、可测量的知识点名>",
                    "explanation": "<该知识点的真实讲解>",
                    "questions": [ <题目6元组>, ... ],
                },
                ...  # 每章恰好 4 个 point
            ],
        },
        ...  # 章数与骨架索引一致，顺序一致
    ],
}
```

## 3. 题目 6 元组

`(qtype, stem, options, answer, analysis, difficulty)`

- `qtype`：只用 `choice` / `fill` / `judge` / `answer`。**不要用 `multiple`**（可避开多选题解析逐项字母的硬规则；少一个题型只是非阻断提醒）。
- `choice`：`options` 为 4 个互不相同的字符串；`answer` 是 `"A"`~`"D"`，且必须真的对应正确项；`analysis` 要说明「所以选 X」并解释其余三项为什么不对。
- `fill`：`options=None`；`answer` 为文字或文字列表；`analysis` 给出填空依据。避免纯数字答案（会触发验算规则），必要时在解析里写出等式。
- `judge`：`options=None`；`answer` 为 `"T"` 或 `"F"`；`analysis` 说明判断理由。
- `answer`：`options=None`；`answer` 为参考答案文字；`analysis` 为分点评分要点。
- `difficulty`：1~5 的整数。每点 4 题建议难度 1/2/3/4 各一。
- 所有题必须有真实、可核对的解析；不得出现「略」「见教材」等空解析。
- **数学/理化解析禁止写连续等式或分数连等式**：校验器会取「算式 = 数字」做验算，`2×3+1=6+1=7`、`2/4=3/EC`、`P=2/6=1/3` 都会被截成 `2×3+1=6`、`2/4=3`、`2/6=1` 而误报「算式不成立」。改写成分步文字，如「先算 2×3 得 6，再加 1 得 7」「AD 与 DB 的比为 2 比 4，放大 2 倍得 EC 为 6」「6 种结果里两白占 2 种，化简为三分之一」。同理避免「数轴上表示」这类含「上表」子串的写法。

## 4. 硬性规则（组装器 `_rerun_books.py self_check` 会拒收）

1. 每章恰好 4 个 point，每个 point >= 4 题；point 名不得含 `·概念` / `·理解` / `·认知` / `·概念理解` 之类占位后缀，必须是可测量的知识（如「凸透镜成像规律」「两位数乘一位数的进位」）。
2. 全册题干（按 `qtype + stem`）互不重复；point 名互不重复。
3. 题干禁止命中负面清单：`更可取的学习做法`、`可以先梳理`、`举一个生活中用到`、`结合实例分析比单纯背诵`、`值得提倡的`、`知识脉络`、`·概念理解`、`·认知`、`先理解概念再结合实例分析`。
4. **每章题量必须 18~28 道**（`_validate_daily.py` 整册硬规则）。4 点 × 4 题 = 16 题/章，因此必须照黄金样例文件末尾的 `_REVIEW_Q` 字典，为每章再补 2 道「章末综合情境题」，并在文件末尾用 for 循环 append 到对应 point.questions，使每章正好 18 题。章末题也要是真实情境题，挂在该章已有知识点上。
5. 题目内容必须是**本学科、本年级、上册**的真实知识点与具体情境，按该册教材常识编写；严禁把同一套句子替换章名复制，严禁复用其他年级的题目，严禁空泛评价（「很重要」「很有意义」不能当解析）。
6. 章名必须逐字取自骨架索引，顺序一致；`version` 取 `tasks.json` 的 `expected_version`（常用：语文人教版、数学北师大版、英语牛津深圳版、道法/历史部编版、物理/化学/生物人教版、地理湘教版）。
7. 英语册题干与选项用英文、解析用中文；数学/物理/化学计算题解析写出公式与代入；历史时间人物事件要准确，不编造史料。

## 5. 输出长度控制（章数多的册必读）

章数可达 13 章、每章 18 题（最多 234 题）。为保证草案一次输出完整、不被截断：

- 每题题干 ≤ 40 字；`choice` 的每个选项 ≤ 14 字；解析 ≤ 45 字（1-2 句，写清依据与「所以选 X」即可）；
- `answer` 题参考答案 ≤ 60 字、评分要点 ≤ 45 字；
- 知识点 `explanation` ≤ 80 字，不要写冗长史实铺陈与多句排比；
- 每题一个 6 元组、占一行，不换行；
- 目标：单册草案 ≤ 30000 字符。内容仍需真实、可核对，紧凑不等于空泛。

## 6. 分片模式（章数 ≥ 10 或单册输出会被截断时）

一次输出 200 题容易超出子代理单次输出上限而被截断（表现为文件里没有完整 ```python 块、只剩尾部片段）。此时按章拆成 A/B 两段，每段约一半章数，主代理用 `_extract_pack.py --batch` 把两段代码块顺序拼接成同一个 pack 文件。

- **A 段**（负责前半章）代码块必须是可直接执行的完整开头：

```python
# -*- coding: utf-8 -*-
PACK = {"subject":"<学科>","grade":<年级>,"version":"<版本>","semester":"first","chapters": []}
PACK["chapters"] += [
    {"name": "<骨架第 1 章>", "summary": "...", "points": [...]},
    ...  # 直到第 ceil(N/2) 章
]
_REVIEW_Q_A = {"<骨架第 1 章>": [(0, <6元组>), (1, <6元组>)], ...}
for _ch in PACK["chapters"][:ceil(N/2)]:
    for _idx, _q in _REVIEW_Q_A[_ch["name"]]:
        _ch["points"][_idx]["questions"].append(_q)
```

- **B 段**（负责后半章）代码块**不要重复定义 PACK**，直接续写：

```python
PACK["chapters"] += [
    {"name": "<骨架第 ceil(N/2)+1 章>", "summary": "...", "points": [...]},
    ...  # 到最后一章
]
_REVIEW_Q_B = {"<后半章名>": [(0, <6元组>), (1, <6元组>)], ...}
for _ch in PACK["chapters"][ceil(N/2):]:
    for _idx, _q in _REVIEW_Q_B[_ch["name"]]:
        _ch["points"][_idx]["questions"].append(_q)
```

两段各自为**完整 python 代码块**，章名严格按骨架索引顺序、不得重叠或遗漏；每章仍然 18 题。B 段不得写 `# -*- coding -*-`、不得重新赋值 PACK、不得写 import。

## 7. 输出方式（重要）

执行者若是只读子代理：**不要尝试写文件或执行命令**，只需在最终回答里输出**一个**完整的 ` ```python ` 代码块，包含从 `# -*- coding: utf-8 -*-` 到最后 for 循环的全部内容。禁止省略、禁止 `...`、禁止拆成多个代码块、禁止只给大纲。代码块外只用一句话说明草案的册名、章数、题数。

主代理会用 `_extract_pack.py` 把代码块落盘，再运行：

```
python _rerun_books.py --check --pack <pack_name>
python _rerun_books.py --pack <pack_name>
python _validate_daily.py <产出文件> --version-map ... --json-out ...
python _check_book_gate.py <产出文件> --json-out ...
```

要求：自检通过、校验器 0 错误、P3 闸门全 PASS。
